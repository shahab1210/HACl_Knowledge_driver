# P13 — MQTT + AI Integration Layer

The **P13 MQTT + AI Integration Layer** bridges the IoT telemetry stream (generated by the ESP32 simulator and transmitted via Mosquitto MQTT) with the local AI fault diagnosis pipeline (P12 `DiagnosisEngine`, P11 `RAGLLMPipeline`, P10 Ollama LLM, P9 RAG, P8 ChromaDB Vector DB).

---

## 1. System Architecture

```text
               IoT Sensor Simulator
               (Iot_hcl_Python/mqtt_sender.py)
                        │  (Topic: iot/ESP32_001/telemetry)
                        ▼
               Mosquitto MQTT Broker (localhost:1883)
                        │
         ┌──────────────┴──────────────┐
         ▼                             ▼
Spring Boot Subscriber        P13 MQTT Telemetry Subscriber
(PostgreSQL / Grafana)        (ai-diagnosis-subscriber)
                                       │ (JSON Payload)
                                       ▼
                              Telemetry Parser & Validator
                                       │ (TelemetryMessage)
                                       ▼
                              Bounded Worker Queue (maxsize=50)
                                       │ (Decoupled Thread)
                                       ▼
                              P12 Diagnosis Engine
                                       │ (RAG + Ollama LLM)
                                       ▼
                              MQTT Diagnosis Event
```

### Key Design Principles:
1. **Decoupled Asynchronous Execution**: Direct LLM inference takes 5–60 seconds. Invoking inference inside the MQTT `on_message` callback would block the network loop and cause broker disconnects. Telemetry is parsed, validated, and pushed onto a thread-safe bounded queue (`AIWorker`), allowing the network loop to return in `< 1ms`.
2. **Schema & Anomaly Awareness**: The validator verifies structural integrity and numeric bounds while ensuring abnormal telemetry values (e.g., $95.0^\circ\text{C}$ temperature, $7.2\text{ mm/s}$ vibration) are preserved as valid fault indicators.
3. **Sliding-Window Deduplication**: Avoids duplicate RAG/LLM inferences for identical sensor readings within a configurable window.
4. **Resilient Failure Handling**: Worker queue overflows drop messages gracefully with logging, and LLM inference timeouts or errors do not crash the subscriber.

## 3. Telemetry Payload Schema

The system consumes JSON telemetry conforming to the ESP32 simulator and Spring Boot subscriber schema:

```json
{
  "device_id": "ESP32_001",
  "temperature": 95.0,
  "humidity": 45.5,
  "vibration": 7.2,
  "current": 8.4,
  "pressure": 2.1,
  "recorded_at": "2026-10-01T01:00:00"
}
```

Field aliases such as `deviceId`, `temp`, `vib`, `currentValue`, `timestamp` are automatically supported.

## 4. Python API Usage

### Example: Running the Service Programmatically

```python
from config import MQTTConfig
from service import MQTTDiagnosisService
from models import MQTTDiagnosisEvent

def handle_diagnosis(event: MQTTDiagnosisEvent):
    print(f"Device: {event.device_id}")
    print(f"Primary Fault: {event.diagnosis.primary_fault}")
    print(f"Confidence: {event.diagnosis.confidence.level}")
    print(f"Inference Latency: {event.latency_seconds:.2f}s")

config = MQTTConfig(
    host="localhost",
    port=1883,
    topic="iot/ESP32_001/telemetry",
    client_id="ai-diagnosis-subscriber"
)

service = MQTTDiagnosisService(config=config, on_diagnosis=handle_diagnosis)
service.start()

# Keep main thread alive or do other work...
# service.stop()
```
